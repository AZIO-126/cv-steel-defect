# Phase 6 — Report + presentation

**Owner** all three · **Day 11–17** · **Worth 5 (abstract) + 10 (conclusion) + 20 (presentation)**

## Grading criteria (verbatim)
> Abstract — Written collaboratively, briefly summarize the problem, your approach, and describe results.
> Conclusion — Conclude the paper with a discussion of findings, references, and resources for interested readers.
> Please include author names and tables of contents in your final report.
> Please include links and references and sources where you reused the code. algorithms or patterns.
> Each team will be given 20 minutes to present their portion of the project (approximately 5 mins per member).

## Steps
1. Assemble the report from `report/*.md` + `outputs/metrics/*.json` + `outputs/figs/`.
   Because metrics were written to files in phases 3–5, nothing needs re-running here.
2. **Abstract** — each member writes 2 sentences on their own part; lead merges.
   The rubric says "written collaboratively", so this is not one person's job.
3. **Conclusion** — all three required elements, the last of which teams routinely omit:
   **findings** · **references** · **resources for interested readers**.
4. **Three hard formatting requirements** (explicitly in the rubric, cheap to lose):
   - all three **author names**
   - a **table of contents**
   - **links and sources for every reused code snippet, algorithm or pattern**
     (segmentation-models-pytorch, albumentations, any Kaggle kernel consulted)
5. **Slides** — 20 minutes / 3 members ≈ 6.5 min each; each person presents the phase they
   owned, so the split needs no rehearsal negotiation.
6. **Freeze on Day 15 (8/13).** The final two days are rehearsal only. Note 8/15 collides
   with another commitment, so nothing should still be under construction that morning.
